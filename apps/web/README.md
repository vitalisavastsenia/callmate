# Zeus Llama web UI

React + Vite + TypeScript + Tailwind. English UI, Spanish, Russian, English, or Polish haircut transcripts with English translations, and the gold/dark Zeus Llama theme.

The UI follows [delivery-plan section 4](../../docs/mvp-delivery-plan.md#4-engineer-1-ui-and-user-workflow) and [requirements](../../docs/requirements.md). See [UI-CALIBRATION.md](UI-CALIBRATION.md) for delivered scope, verification, and integration dependencies. This is a complete simulated UI workflow, not a completed real-call PoC or integrated personal MVP.

## Start in Docker

Install Docker Desktop. From the repository root:

```sh
docker compose up --build -d --wait
```

Open `http://localhost:3000`. Create the owner account on first use, then sign in on later visits. Passwords must be 12–128 characters at setup. The app remains unmounted until the backend verifies the session, even in simulator mode. **Sign out** revokes the session; other tabs lock on their next API request, focus, or periodic check. Sessions expire after 12 hours. See [local account recovery](../../docs/docker-development.md#16-owner-login-and-sessions). Node.js and dependencies run inside the container. The root Compose file starts two containers: `zeus-llama` serves this built UI and the API, and `mock-relay` serves the operator. The UI uses the browser simulator by default. Rebuild `zeus-llama` after changing frontend source or build-time defaults. `VITE_*` values are public configuration; never put credentials in them.

For hot reload, `docker compose --profile dev up --build -d --wait` adds Vite at `http://localhost:5173`; the normal app at port 3000 keeps serving the compiled build. Browser storage belongs to each origin, so old port-5173 simulator records/preferences remain there; SQLite-backed records are shared.

The workspace builds the shared contracts before starting. Simulator calls need no provider credentials or microphone and make no real calls. Simulator history, plans, pending commands, and settings are stored in this browser's local storage. Clearing browser storage removes simulator history. Contacts always require the backend and persist in its SQLite Docker volume, independently of the selected call mode. Use synthetic data during development.

## Demo workflow

Navigation is **Home · Request · Summary · Agreements · Contacts · Settings**; the active page is filled gold. **Contacts → Create contact** opens a form requiring name, phone (country code supported; Spain is the default), and IANA timezone (Europe/Madrid by default). Country code and timezone use dropdowns. For known country codes, timezone suggestions follow the selected country until explicitly changed; saved timezone aliases are preserved. The phone field also accepts pasted international numbers; choose Other (full number) for an unlisted dialing code. CSV/vCard imports offer the same timezone dropdown. Tone preferences and notes are optional. Search by name/phone; **Edit contact** opens the same form and offers **Delete contact** with confirmation. Saves wait for backend acknowledgement; validation, duplicate phone, and connection errors keep entered values for correction or retry. Existing requests keep their copied destination details after edits/deletion.

1. Home keeps the hero, mascot, English goal field, and optional template chips. **Who should Zeus call?** reuses the searchable contacts picker or accepts a required name, country code (Spain +34 by default), and phone number. Spaces/dashes are accepted and phone numbers normalize to E.164; invalid numbers show an inline error. **Prepare the plan** stays disabled until goal, name, and a valid phone are present, with a missing-fields hint. It parses the goal in simulator mode while preserving the destination you entered. A complete request opens the **Zeus will…** review card. If parsing fails or other required details are missing, the UI shows “Couldn't understand everything — fill in the details” and opens Request with recognized values preserved. No call starts during parsing or review.
2. Request uses five numbered cards on a consistent twelve-column grid, plus a collapsed Advanced card. It remains the full manual form: **Who to call**, request type and goal, relevant appointment/question/change fields (including maximum service price), **Tone & manner**, **Boundaries**, **What Zeus may share**, and collapsed **Advanced settings**. The hero's **Request tab** link and **Enter details manually** open the same draft. Goal, name, country code, and phone stay synchronized in both directions across navigation. Templates use synthetic business destinations and never invent a user's personal name; replace example details before real use.
3. The shared **Name** combobox searches saved names and phone numbers with keyboard selection, or accepts a new name. Name, short country code, and phone occupy one row on wide screens and stack on narrow screens. A chosen contact fills business name, phone, timezone, tone, and notes. Manual numbers have a country-code selector defaulting to +34. **Save to contacts** opts in to saving a new number when a valid review is prepared on Home or Request. Both pages hide this checkbox for numbers already in contacts, including manually entered matching numbers. Edits apply to the request; use the edit dialog to update a saved contact. Changing a selected contact's number saves a separate contact when opted in.
4. The edit icon beside a selected contact opens a compact dialog to edit or delete it. Escape closes dialogs; deletion needs a deliberate confirmation and leaves the current request's copied details intact. The final dropdown item, **Import contacts (.vcf / .csv)**, opens a file picker and column-mapping dialog. Map name/phone, choose the country code for local numbers and a default timezone, then import. Duplicates are skipped by normalized phone, including duplicates within the file; invalid rows are counted. CSV needs a header row and supports quoted fields; vCard supports FN/N, TEL, folded lines, and multiple phones. Files are limited to 2 MB.
5. Tone chips are **Very polite**, **Formal**, **Friendly**, **Firm**, and **Speak slowly**. **Notes for Zeus** starts with any saved contact notes and remains editable. These are visible in the plan summary and sent as `tone`, `tone_notes`, and optional `contact_id` inside the shared plan request.
6. Five quick-add approval chips cover different days/times, prices above your limit, deposits/prepayments, extra personal data, and anything outside your request. Rules remain editable; chosen suggestions move into filled tags and return when removed, removal uses compact icons, and Add controls are lightweight text buttons. Shareable name, callback number, and email remain separate from destination contacts. Settings owns their remembered defaults; request-only edits do not overwrite defaults. Clearing a request field withholds it for that request. Boundaries use editable removable tags, dashed quick-add suggestions in both columns, and **+ Add custom…** as the last option.
7. **Advanced settings** starts closed and summarizes timezone, maximum call duration in minutes, and estimated call cost in the selected transport's settings currency (USD or EUR). The timezone follows known country codes until manually edited or a contact is selected. Country defaults are suggestions for review, especially for countries with multiple zones. Minutes convert to the existing seconds field on submission; 0.5–10 minutes corresponds to the shared 30–600 second limit. A saved draft in a different budget currency needs an explicit new limit; no currency conversion is inferred.
8. A full-width sticky bottom bar reserves its measured height below the page content, shows a short readiness count and disables **Review call plan** until valid. Fields show red outlines and inline messages after being touched or submitting a review; a fresh form shows no errors. **Review call plan** validates the manual form and displays the compact **Zeus will…** card, including tone and notes. Invalid/missing details remain editable and no Call button is offered for an invalid draft. Edits invalidate the prior review. **Call** requires confirmed backend readiness, saves the reviewed request through the existing plan API, and starts one attempt. Backend-normalized plans require another deliberate Call. The simulated outcome selector lives in Settings and retains all existing demo branches. Booking-only scenarios fall back to the information script for non-booking requests.
9. Starting or restoring an active call opens a **Call with…** popup. Its header and close button stay visible while the content scrolls separately within the window. Its Conversation pane distinguishes **Agent · Zeus** phrases from **Business · Other side** replies, with original conversation-language text, English translations, and provisional/playback/interruption labels. New text follows the latest message unless you scroll back. The **Agent decisions & actions** pane records observed offers, approval reasons, read-back, waiting for confirmation, and outcomes. These are summaries of received workflow states; earlier actions may be unavailable after reload. Approval receipts stay in the transcript and are separate from business confirmation. **Minimize call**, the close button, or Escape closes only the popup; the same call continues in the inline view. **View call** reopens it from any page without a new Start. The popup stays open at the end so you can review the conversation and result, then choose **View in Summary**. **Stop call** requests hangup. Exact-offer approval controls are available inside the popup or inline; a sticky attention panel offers direct answers elsewhere when the popup is closed. Approve/reject remains bound to the plan/offer version and expiry and disabled while disconnected. On first call start the UI requests notification permission and unlocks a short sound. Background approvals flash the title and, when permitted/supported, notify and chime; notification clicks open the call popup. Alerts stop when resolved/expired. A lost Start response shows **Check original Start request**, including after reload; retries reuse the original command key. Navigation preserves drafts and active calls, and another attempt remains blocked while one is active or unresolved.
10. The finished-call window offers **Call again** to start a new attempt with the same reviewed request. The button is unavailable during an active call or unresolved Start; a backend-adjusted plan requires another review, and a lost Start response opens the original-command recovery controls. Results link to **View in Summary**. Summary shows newest-first cards with business, date, request type, status, a one-line result, **View details**, and **Repeat**. More than five calls reveals combined search and status filters; zero matches offers **Clear filters**. Each Repeat fetches the saved request and opens the full editable Request form without reviewing or dialing automatically; uncertain results retain a verification warning. Details include agreements, findings, next steps, charges, and transcripts. Confirmed results alone enable calendar export. **Delete conversation text** retains structured data. New review/call/result/detail sections scroll into view and respect reduced-motion preferences.

Summary's **Needs your attention** section appears only while the current call has an unexpired approval awaiting an answer. It updates from the subscribed call snapshot even while you stay on Summary; **Answer Zeus** returns to the exact offer. Answering, expiry, or ending the call removes it. Ordinary in-progress calls keep a return action without showing the attention section. Future booked appointments are not scheduled outbound calls. The existing API and simulator have no scheduled-call records or scheduling operation, so there are currently no calls-to-dial-later to show; wiring a future scheduler requires its data source, not interpreting appointment dates as call schedules.

History badges are **Booked** for confirmed appointments, **Answered** for fully resolved information requests, **Needed you** for follow-up/uncertain outcomes or an unaccepted policy boundary, **Failed** for unsuccessful calls, and **Cancelled** when the call was stopped. The recorded summary explains what happened; Cancelled describes the call attempt and does not claim an existing appointment was cancelled. Uncertain results also keep a visible verification warning. Ongoing calls show **In progress** or **Waiting for you**. With no calls, Summary shows the mascot, “Zeus is resting. Give him something to do.”, and **Create a request**, which opens Home.

Destination contacts use the shared `/api/v1/contacts` backend routes through `src/contacts.ts` in both Simulator and Live modes. The frontend caches acknowledged records in memory and reloads on focus; failed mutations never fabricate successful saves. The old `zeus-llama.contacts.v1` browser copy remains untouched: Contacts offers **Import previous browser contacts** to copy valid records into SQLite, skipping duplicate normalized phones. CSV/vCard imports and opt-in saves in Home/Request use the same address book. Imports use batches of at most 100 records and approximately 60 KB; an interrupted multi-batch import may have saved earlier batches and can be retried safely by phone deduplication. Shareable user details use their existing independent storage key. Settings uses the existing settings API for duration, call-cost and retention defaults, preserving the configured budget currency; shareable contact defaults and timezone are local browser preferences. Existing draft edits survive navigation and mode changes; untouched fields receive saved defaults. When the budget currency changes, edited call-cost amounts are cleared for explicit re-entry and the plan requires review. Real calls remain readiness-gated.

Scenarios: within-plan confirmation, alternative time, price above limit, changed offer, disconnect near confirmation, no answer, and interrupted assistant speech. Approve/reject/expiry and Stop create additional outcome branches. Script updates are 1.8 seconds apart; the offer normally appears in about 9 seconds. Non-booking calls use a separate information script and never enter appointment acceptance. The clinic template supplies an example identification/medical-records answer, while referral requirements remain open. Arbitrary questions are explicitly unanswered; custom tasks and change/cancel requests finish with follow-up needed. The simulator does not execute arbitrary goals or actually change/cancel existing bookings. Booking-only price/time scenarios use the information script for other request types; no-answer, interruption, and uncertainty remain available.

The fake backend enforces its 30-second approval deadline, one-active-attempt check, duration cap, and synthetic estimated-spend cap. Do not interpret these as provider guarantees.

Refreshing restores the same attempt, never starts another one. While no tab is running the fake backend cannot execute code; on return it checks saved state/deadlines and resumes. Real calls must continue independently in the actual backend.

## Agreements

**Agreements** shows all confirmed appointments and answered findings from calls in List or Calendar view, with search and type filters. The list separates upcoming appointments, other agreements, and past appointments. The Monday-first monthly calendar supports previous/next month, Today, date selection, and a daily agenda; **Show in calendar** opens an entry’s date. **View call details** opens its original Summary and transcript without dialing.

Appointments use the confirmed offer’s business-local date, time and timezone, including after transcript deletion. Other agreements use the call’s recorded date in the viewer’s timezone, explicitly labelled **Recorded on**; free-text dates and proposed availability are never turned into scheduled events. Only answered findings appear as agreements; open next steps stay labelled as follow-up. Uncertain, failed, pending and manual-console calls do not become agreements. Simulated records retain their simulation label. Both call modes use their existing complete paginated history and the current subscribed snapshot; this view introduces no separate storage or outbound-call scheduling.

**Delete entry** asks for confirmation and removes a finished call’s entry from both Agreements views after storage acknowledges the change. This does not cancel an appointment with the business. Summary retains the original call, result, and any retained transcript. Backend mode stores the deletion timestamp in the SQLite snapshot; browser Simulator stores it in localStorage. Removal survives refresh/restart and transcript retention. Failed deletions keep the entry and allow retry; active calls cannot be deleted. Use Refresh agreements to see changes made in another tab.

## Shared client boundary

- `src/types.ts` re-exports/inferences the executable `@callmate/contracts` v1 schemas/types. No frontend copies of the wire schemas.
- `src/api.ts` owns all HTTP requests and uses the exported `api` methods, paths, request schemas, and response schemas. REST requests have 15-second timeouts. It checks HTTP status before reading errors as text, parses only nonempty `application/json` bodies, and treats 204/empty bodies as null. Required snapshots/settings still need their agreed schema and produce a friendly status-bearing error if absent; a deletion may return null, after which the UI refetches the authoritative call. Invalid JSON, HTML responses, and schema mismatches never fabricate readiness or successful calls. Failed URLs and HTTP statuses (or an unavailable network status) are logged to the console. Structured API error codes/details remain available. No automatic redial or new Start key is generated on errors.
- `src/ws.ts` retains the original boundary filename but now implements **SSE** per shared v1. Fetch streaming sends `Last-Event-ID`, including zero. It validates envelopes, deduplicates sequences, and refetches authoritative snapshots. EOF, gaps, reset frames, malformed/unknown events, and incompatible messages cause snapshot resynchronization with backoff capped at 15 seconds. Unsubscribe aborts the stream/timers. Transcript updates are replaced from the authoritative snapshot, keyed by message ID.
- `src/mock.ts` is the in-browser fake backend, using the same validated plans/snapshots/events/settings. Real mode never invokes it.
- `src/calendar.ts` exports only schema-valid confirmed outcomes. UTC `DTSTART` preserves the exact instant across DST; `X-WR-TIMEZONE` and the description retain the original IANA zone and business-local date/time. Unknown duration is explicitly described and produces neither `DTEND` nor `DURATION`. Text is escaped and UTF-8 lines folded for valid `.ics` output.

The earlier provisional `/api/plan`, `/api/call`, escalation and WebSocket contract is retired in favor of the repository's agreed `/api/v1` HTTP/SSE contract. The generic request and non-booking outcome extension is defined centrally in the shared schemas; see the [message contract](../../docs/ui-message-contract.md#generic-request-extension). No server/dialogue implementation is changed. Backend consumers must adopt the extension, including tone/notes/contact references, before accepting updated UI plans; this is not an assertion that an older live backend supports them.

Settings is the single place to switch **Simulator / Live**, with the selection remembered on this device. `VITE_MOCK` supplies the build-time initial mode only when no selection is saved. Switching modes reloads readiness, settings and history for the chosen transport while preserving the current draft. Active, pending, or unresolved attempts lock mode switching. For a backend implementing v1, start the server with `docker compose up --build -d --wait zeus-llama` and choose Live in Settings. Leave `VITE_API_URL` unset/empty to use the same-origin API served by Zeus Llama. In the optional dev profile, Vite proxies `/api` (including SSE) to the Compose server using `CALLMATE_DEV_API_TARGET=http://zeus-llama:3000`; its fallback outside Compose is `http://127.0.0.1:3000`. The development proxy sends the loopback Host expected by the private API and translates Origin only for loopback HTTP UI origins (`localhost` or `127.0.0.1`) matching the incoming UI port; other Origin values remain unchanged for backend rejection. Keep browser and API requests on the same origin so REST and SSE carry the HttpOnly session cookie. This backend does not enable cross-origin credentialed access. For a different backend, change the development proxy target; a separately hosted UI needs a same-origin reverse proxy. The resolved base is printed once per page session on the first entry to Live mode. Production hosting must route same-origin API paths and permit streaming without proxy buffering.

Network failures/timeouts and unreachable development-proxy responses show “Can't reach the Zeus backend. Check that it's running, or switch to Simulator in Settings.” with **Switch to Simulator**. This keeps the current draft. Switching stays locked for active/pending/unresolved attempts so a lost Start cannot be abandoned or duplicated. Real Start remains disabled until backend readiness is known/ready. Before real use, replace synthetic fixture details and use a consenting test destination. Provider setup, SQLite, actual authority enforcement, restart reconciliation, and actual usage/retention remain backend responsibilities.

## Verification

From repository root:

```sh
docker compose --profile checks run --build --rm checks
docker run --rm --ipc=host -e PLAYWRIGHT_CHANNEL=chromium callmate-checks sh -c 'npx playwright install --with-deps chromium && npm run test:e2e --workspace @callmate/web'
```

The first command builds all workspaces and runs type checking and offline unit/contract/server tests. The second installs Chromium and its OS dependencies only inside a disposable container and runs the browser tests. It requires network access for installation. `PLAYWRIGHT_CHANNEL` selects bundled Chromium for Docker (including ARM64); the existing default remains Google Chrome. Browser tests launch isolated headless profiles and UI test servers on loopback ports 5174/5175, plus a local backend on port 3000 with a temporary SQLite database at `/tmp/callmate-contacts-e2e`. An automatic fixture authenticates a test-only owner and clears contacts in that isolated database between cases. Auth tests reset only this disposable owner and verify setup/login/logout and locked UI states on both viewports. Contact tests use real HTTP/database persistence; call tests retain their browser simulator or intercepted HTTP/SSE responses. No providers are contacted and the live Docker data volume is never mounted. Browser tests are separate from `npm test`. The `production` and `production-narrow` projects check the built UI served by the application, asset URLs, same-origin API access, and the shared console session. Set `CALLMATE_E2E_APP_URL` to an isolated deployed test stack and run only those two projects to skip the local test servers; that target must be disposable because the fixture creates a test owner and clears contacts.

Vitest covers shared-client HTTP/SSE behavior, cursor resynchronization, calendar correctness, DST, idempotency, versioned approvals/expiry/rejection, Stop, limits, deletion, persistence, and evidence-based outcomes. Playwright covers Home parsing/fallback, the full manual Request on desktop and 390px layouts, contact selection/save/update/edit/delete, CSV/vCard import and deduplication, tone/notes in plans, minute conversion and timezone overrides, Settings defaults and draft-only sharing edits, runtime mode switching/guards, global/offscreen approvals and background notification behavior, Summary/Repeat, calendar/download/deletion, uncertainty, Stop/double Call, refresh/expiry, changed offers, keyboard access, HTTP/SSE resynchronization, backend-adjusted plans, and lost Start response recovery. Browser artifacts in `test-results/` are ignored.

Call-budget amounts and labels follow the active settings currency: the browser simulator defaults to EUR, while the backend may use USD or EUR. The request form and Settings both preserve that currency. Service-price limits remain EUR and are independent of call charges. Switching currency invalidates the reviewed plan: untouched default amounts can use the new transport's configured default, while edited amounts and saved drafts in another currency require a new amount in Advanced. No FX conversion or relabeling of saved amounts is performed. The backend continues rejecting mismatched currencies.

## Fill details from the goal

In mock mode, enter an English goal and destination on Home and click **Prepare the plan**. Request also offers **Fill details from goal** without requiring automatic parsing for manual review. No destination/name/contact data is invented. Gold outlines and “Auto-filled” badges mark suggestions, and editing a field clears its marker. Existing manual detail values are preserved; a new inferred request type can reveal the appropriate fields. Clicking again replaces old unedited suggestions and clears suggestions no longer present in the goal. Templates reset suggestion markers. Preparation does not save a plan, start a call, or widen booking authority; contact saving is separately opt-in.

The simple rules recognize explicitly named/quoted destinations and international phone numbers, unique saved contacts, stated tone preferences, request type, common services (haircut, vet, dental, rabies vaccination, medical appointment) or a short “book …” phrase, basic EUR cap phrases (such as “up to €30” or “don’t agree to more than 60 euros”), explicit questions, booking references, and stated independent-decision/approval constraints. Dates support `YYYY-MM-DD`, English month/day, today, tomorrow, and upcoming weekdays including “next Tuesday”, resolved in the destination timezone. A weekday resolves to its next occurrence (strictly after today); an omitted year uses the current destination-local year. These interpretations are shown for review.

Times support AM/PM, 24-hour ranges, “between 5 and 7 pm”, “from 17:00 to 19:00”, and partial “after/before/at” phrases. Missing end/start times stay empty. Invalid dates, past dates, multiple dates, ambiguous clock times and reversed/overnight ranges require manual completion. Existing DST validation still runs before review. Only simple decimal EUR amounts are supported; there is no currency conversion. Cancellation dates are not treated as new availability.

`src/api.ts` exports the single asynchronous `parseGoal(goal, context)` entry point. It dispatches to the pure `src/goalParser.ts` rules in mock mode; it is disabled in backend mode until a real endpoint is agreed. Future LLM integration belongs in this API function, with a validated suggestion response. Editable suggestion types in `src/types.ts` stay separate from the resolved shared request/plan schema. No provisional endpoint, credentials, or browser model SDK is introduced.

## Integration branch limits

This merge preserves both workstreams; it does not complete their end-to-end integration. The backend simulator currently accepts appointment requests only and requires an approved booking name. Generic ask/change/other requests receive `400 INVALID_REQUEST`. Tone/notes/contact references persist with plans, but free-text boundaries still need backend policy adoption before live calling.

Call budgets must match the currency in backend settings; no FX conversion is performed. Explicit USD test rates reject EUR call budgets. With test rates disabled, provider charges remain unavailable. The shared history can include `kind: "manual_mock"` entries with no booking plan; the booking UI reports that these must be viewed/controlled in the backend console at port 3000. Its standalone simulator emits the current readiness capabilities contract. Live telephony remains disabled. The optional backend dialogue path analyzes Spanish, Russian, English, and Polish haircut inquiries and returns policy-approved relay replies; see [setup and limits](../../docs/docker-development.md#17-dialogue-driven-local-mock-calls). Select **Settings → Backend**, choose **Conversation language** in the request form, review the plan, and answer in the local mock operator window. It does not yet accept or confirm bookings.

The reviewed language persists in drafts/plans, repeat calls, and history. Request review displays it before Start. Assistant transcript messages can carry stable, versioned phrase references; display the supplied rendered text and English translation, not a client-side reconstruction from IDs. The reusable translations live in backend SQLite. Existing drafts without a language remain Spanish. The browser simulator keeps its Spanish script and rejects another selected language with a prompt to use Backend.

**Conversation template** on Home and Request offers all 15 domain profiles. Choosing one preserves the destination, language, owner name, availability and price cap, and resets domain details and acceptance authority to explicit approval. Required coded choices/numbers and the bounded vehicle make/model field must be completed before review. Request review and offer views display these details; editing them invalidates the previous review. Editing service outside the selected profile clears that profile and its details. The 14 new profiles require Backend mode with the configured dialogue model/mock; the browser simulator does not substitute a haircut script. See [profile fields and limits](../../packages/dialogue/README.md#conversation-templates).
